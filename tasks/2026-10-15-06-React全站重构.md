# 2026-10-15 任务 06：前端全面重构 —— React + TypeScript + Vite 替换原版 LuCI 前端

**目标**（机主需求，原文要点）：
1. 原有前端 bug/冲突多、混用原版 LuCI 页面 → **删掉自带前端，全面换成 React + TypeScript + Vite**
2. 连接后不应自动打开"路由可视化"→ **每次打开自动进入首页，首页放菜单最上面**
3. 首页展示**本月上行/下行流量**、**哪个 IP 跑得最多**；IP 下钻能看到具体连接（链接/目标）以便**追踪**
4. **性能最近历史记录**（性能曲线）
5. **背景图很多页面（如路由可视化）不生效** → 在设置里加**个性化**统一管理背景图

## 结论（先说架构变化）

旧架构问题根因：
- 控制台 SPA 是**预编译产物**（源码不在仓库），且把原版 LuCI 页面以 **iframe** 嵌入 → 英文菜单、白色 LuCI 主题、"Loading view…" 与自研页面互相打架；仓库里还残留 3 个历史构建的 `index-*.js` 互相冲突。
- 自研 Lua controller（`yueyueconsole.lua`）+ 向导（`luci-app-yueyuewizard`）都挂在 **LuCI Lua 调度器**上，页面外壳就是原版 LuCI。

新架构（本次交付）：
```
浏览器 ── React SPA (/luci-static/yueyue/index.html, HashRouter)
   │        ├─ /ubus (uhttpd-mod-ubus)：登录/uci/iwinfo/网络等标准能力
   │        └─ /cgi-bin/yueyue (Lua CGI 统一 API)：流量/性能/个性化/路由/向导/诊断…
   │
OpenWrt ── yueyue-monitor (procd 守护, 30s 采样)
              ├─ /proc/net/nf_conntrack 差值 → 按 IP 月度流量 + 目的地追踪
              └─ CPU/内存/负载/连接数/速率 → 性能历史环形缓冲
```
- **仓库 `ui/` = React 源码**（TypeScript + Vite + react-router，HashRouter 适配 uhttpd 静态托管）
- 构建产物 → `files/www/luci-static/yueyue/`（ImageBuilder `FILES=files/` 直接带进固件）
- **全部自研页面退出 LuCI 调度器**：原 `yueyueconsole.lua` 与 `luci-app-yueyuewizard` 的 Lua 视图/接口已移植到 CGI 后删除，"路由可视化 / 向导 / 流量 / 监控"不再出现原版 LuCI 外壳

## 做了什么

### 1. 后端（`files/`）
- **`www/cgi-bin/yueyue`**（Lua CGI，统一 API，~1000 行）：
  - 认证：`?auth=<sid>` / Cookie `ubus_rpc_session`，经 `ubus call session get` 校验；写操作强制 root
  - 动作：`sysinfo / traffic / flows / perf / topology / route_save / route_delete / layout_save / apply / wizard_* / personalization / bg_upload / bg_reset / diag / log / processes / services / opkg / backup / restore / upgrade / reboot / password / public_info`
  - `bg_upload`：按 magic bytes 识别 JPG/PNG/GIF/WebP/SVG，≤8MB，写入 `assets/bg-custom.<ext>`
  - `backup`：sysupgrade 打包 + 纯 Lua base64 回传（busybox 无 base64 命令）
  - 软件包管理自动适配 **apk**（25.12 已弃用 opkg）/ 旧版 opkg
- **`usr/libexec/yueyue/monitor.lua`** + **`etc/init.d/yueyue-monitor`**（procd 常驻）：
  - 每 30s 解析 `/proc/net/nf_conntrack` 双向字节计数，对 LAN 网段（uci network static 接口）做差值累计
  - 按 `YYYY-MM` 记账：每月总量 + 每 IP 上下行 + **每 IP 目的地 TOP**（dst:port/协议/字节/首末时间）→ 支持"这个 IP 都访问了什么"的追踪
  - conntrack 条目流结束后仍保留数分钟（TCP TIME_WAIT 等），30s 差值采样对长短流都能较好捕获
  - 同时采样 CPU%/内存%/负载/连接数/WAN 速率 → `/tmp/yueyue/perf.json` 环形缓冲（30s × 2880 = 24h）
  - 流量月账本每 10 分钟持久化到 `/etc/yueyue/traffic.json`，重启不丢当月累计
- `etc/uci-defaults/99-yueyue-defaults`：追加个性化默认值 + 自启采样守护

### 2. 前端（`ui/`，React 18 + TypeScript + Vite 5）
- 构建体积：**gzip ≈ 82KB**（vendor 54K + app 25K + css 3K），适合路由器下发
- 全站玻璃拟态主题 + **全局背景层**（`position:fixed` 一个背景层覆盖所有页面）→ 根治"路由可视化等页面背景不显示"
- 18 个页面：**首页** / 流量统计（IP 下钻追踪）/ 实时流量 / 性能监控 / 路由可视化 / 接口 / 无线 / DHCP·DNS / 防火墙 / 网络诊断 / **系统设置（个性化）** / 系统日志 / 进程 / 启动项 / 软件包 / 备份·升级 / 多拨负载均衡 / UPnP + **首次设置向导**（React 重写）
- **首页**（默认路由 `/`，菜单第一项）：本月上行/下行合计大卡、流量最多 IP + TOP5 榜（点击直达下钻）、CPU/内存/运行时间/连接数、最近 2 小时性能趋势、快捷入口
- **流量统计**：月度切换、按 IP 排序表格、点开 IP 弹层 = 本月上下行 + **目的地 TOP（历史累计）** + **实时 conntrack 连接**（协议/目标/端口/状态/双向字节）→ 满足"通过链接追踪"
- **性能监控**：1h/6h/12h/24h 切换，CPU/内存/连接数/速率四组曲线 + 样本明细表
- **个性化**（设置内）：背景图（内置插画 / 上传自定义 / 恢复默认）、遮罩强度、模糊度、卡片圆角、主题色（预设 + 取色器）、深/浅色，**全部实时预览 + 全局生效**
- 登录：ubus `session.login`，会话写入 localStorage + cookie；首次登录（`yueyue.wizard.done=0`）自动进向导

## 避坑

- **OpenWrt 25.12 包管理是 apk 不是 opkg**（`apk list --installed` / `apk add` / `apk del` / `apk search`）
- busybox **没有 base64 命令**，备份回传用纯 Lua base64 实现
- uhttpd 的 Lua dispatcher 不认 `ubus_rpc_session` cookie（`?auth=` 亦 403），自研 API 用 CGI 自校验 `ubus call session get`（返回体在 `values.username` 下）
- **编辑含 `[^\n]` 的 Lua/正则源码时转义极易出错**：edit 工具里写 `\\n` 才是字面 `\n`；曾导致 gmatch 按字符 n 断词、apk 列表解析成碎片
- QEMU user-net (SLIRP) **不转发 ICMP**，虚拟机里 ping 外网必丢包，验证连通性用 TCP
- 本机 PowerShell 内联复合命令（`&` 链 + 引号嵌套）易被 cmd 拆坏 → 写 .sh/.bat 文件执行
- Edge 无头截图沿用旧坑：先按命令行筛杀自家 msedge 实例、每张独立 `--user-data-dir`
