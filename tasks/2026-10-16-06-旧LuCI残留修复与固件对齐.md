# 2026-10-16-06 旧 LuCI 页面残留根因修复与固件对齐

> 任务 14（机主截图反馈：访问 192.168.21.1 依旧出现旧版 LuCI 页面）

## 目标

排查并解决「前端 v2.1.0 已替换原版 LuCI 之后，浏览器里依旧残留旧版本页面」的问题（机主截图：`http://192.168.21.1/cgi-bin/luci/admin/status/overview` 渲染旧版 LuCI Status 页）。

## 根因（三层，均有实证）

1. **演示机跑的是旧基底固件**：QEMU 虚拟机自 2026-10-15 22:03 启动（截图时 uptime 15h07m）从未重刷，磁盘上仍是 **firmware-1.0.0 时代**的完整 LuCI 栈。
   - VM 内实测 `apk list`：`luci-mod-admin-full / luci-mod-status / luci-mod-network / luci-mod-system / luci-theme-bootstrap(3 套主题) / luci-app-*` 全部在位，版本 **26.284.22350~8125d12**；
   - 截图页面固件栏渲染的 LuCI 版本正是 `26.284.22350-8125d12`。
2. **热部署只加不删**：`deploy_ui.sh` 只把新 SPA（`/www/luci-static/yueyue`）、CGI（`/www/cgi-bin/yueyue`）、`index.html`、ACL 覆盖进 VM，**从不删除旧 LuCI**（`/www/cgi-bin/luci` 调度器 + 全部 luci-mod-* + 主题 + menu.d 菜单），所以 `/cgi-bin/luci/admin/...` 旧路由永远可达、永远渲染旧页。
3. **新镜像与旧镜像版本不一致（铁证）**：`F:\linux\firmware-2.1.0\*.manifest`（2026-10-16 13:12 由最新代码构建）里 luci-base = **26.287.39313~74c485a**，且**根本没有** luci-mod-*/luci-theme-bootstrap（ib-packages.txt 已用 `-` 排除）→ 交付固件不含旧页面；截图页面不是新固件渲染的。另：2.1.0 保留 `luci-base`，`/cgi-bin/luci` 入口仍存在（无主题/模块时会露残缺页），旧地址也应被跳转而非露页。

**结论**：不是浏览器缓存问题（LuCI 版本号由服务端渲染），是「旧基底 + 热部署只加不删 + 旧入口未拦截」三件事叠加。

## 做了什么

1. **仓库根治**：新增 `files/www/cgi-bin/luci` —— 旧 LuCI 入口替换为 302 重定向脚本（任何 `/cgi-bin/luci/*` → `/` 新控制台，`Cache-Control: no-store`，附中文过渡页）。随 FILES overlay 进入每个构建，交付固件旧地址永不再渲染旧 UI。
2. **热部署工具更新**：`F:\linux\work\uitest\deploy_ui.sh` 推送列表加入 `cgi-bin/luci`，并在 VM 内 `chmod +x` 两个 CGI。
3. **演示机立即生效**：跑 deploy_ui.sh 热更 VM。
4. **验证**：
   - VM 内 `GET /cgi-bin/luci/admin/status/overview` → **HTTP/1.1 302 Location: /** ✅；
   - `/` 与 SPA 资源正常 ✅；
   - 回归基线 `wf-test.js` **16/16 PASS** + `wf-test2.js` **4/4 PASS**，console 错误 0、失败请求 0 ✅。
5. **固件重打**：`run_ybuild.sh` 由最新代码重建 6 件套，覆盖 `F:\linux\firmware-2.1.0\`（含本修复）。

## 结果

- 旧 LuCI 页面残留已消除：演示机旧路由 302 到新控制台；交付固件内旧入口同样 302。
- 回归测试全绿，无功能回归。
